# 平台治理 V3

本批次把“数据可信、工作高效、性能可解释”作为统一平台能力，而不是分散在业务页面中的临时功能。

## 主数据与数据质量中心

- 覆盖客户、供应商、商品和员工四类核心主数据。
- 规则扫描使用唯一问题键和扫描批次标记，同一问题不会重复创建；后续扫描确认问题消失后自动关闭。
- 严重程度分为严重、警告、提示，问题支持分派、解决和忽略。
- 管理员执行扫描与处置，董事长只读查看；所有读取同时受组织隔离和权限编码约束。
- 首批规则包括客户负责人/联系人/结算主体、供应商信用代码/有效资质、商品主图/条码/有效价格、员工部门/账号绑定。

## 个人工作台与统一表格

- Dashboard 首屏数据改为服务端并行读取，消除浏览器挂载后的二次数据瀑布；手动刷新仍保留。
- 每位员工可保存常用入口、隐藏组件、显示密度、默认工作区及完整/窄栏模式，账号偏好受组织隔离并跨设备生效；完全隐藏侧栏仅保存在当前浏览器。
- 统一 `AppShell` 提供桌面三态侧栏、移动抽屉、统一顶部栏、权限过滤和键盘操作。页面内容偏移由 CSS 变量控制，不再由业务页维护固定左边距。
- 命令中心支持 `Ctrl/⌘ + K`、最近访问、权限内模块跳转和业务搜索入口。
- `BusinessDataTable` V2 提供服务端排序、列显隐、固定列、批量选择、批量操作、导出、移动卡片模式和跨设备保存视图；业务页面可渐进接入同一接口。
- Dashboard 的销售趋势、订单价型和商品排行来自真实订单；数据不足时显示空状态，不混入模拟经营数据。

## 性能监控和慢查询治理

- 应用性能事件记录路由、操作、耗时、结果和有限元数据；单用户每小时最多 300 个样本，元数据最大 4 KB。
- 性能中心展示平均延迟、P95、错误率、慢请求数和路由热点。
- 数据库慢查询依赖 `pg_stat_statements`。页面只展示 SQL 的 MD5 指纹和聚合指标，不返回原始 SQL。
- 观测事件默认按 30 天保留，管理员可通过受控函数清理；生产环境应配合 Supabase Cron 或外部调度器定期调用。

## 上线顺序

1. 按时间顺序应用数据库迁移，应用版本升级前必须先应用 `20260904115539_next_stage_shell_and_finance_close.sql`。
2. 确认自定义角色已重新发布或继承系统管理员/董事长权限。
3. 由管理员首次执行主数据扫描，分派存量问题。
4. 访问 Dashboard 产生性能基线；如需数据库慢查询摘要，在 Supabase 控制台启用 `pg_stat_statements`。
5. 观察至少一周后，以真实 P95 为基准设置告警阈值，不建议直接使用固定通用阈值。
