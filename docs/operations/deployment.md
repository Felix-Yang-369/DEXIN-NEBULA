# 部署与回滚规范

## 当前正式入口

- 业务系统：`app.nebula.dexinmiaosheng.cn`
- 产品介绍站：`nebula.dexinmiaosheng.cn`

两个域名不得配置到同一应用入口，生产登录回调不得指向产品介绍站。

当前业务系统以阿里云 ECS 生产部署为准，Vercel 保留上一版本部署作为额外恢复来源。部署前必须先通过完整构建验证。

## 通用发布规则

1. 确认本次发布范围、数据库迁移和回滚方式。
2. 不上传 `.env.local`、本地缓存、`node_modules` 或真实测试数据。
3. 在隔离环境安装依赖并完成生产构建。
4. 构建成功后验证登录、权限和关键业务路由。
5. 发布后核对正式域名、身份回调和服务日志。
6. 验证失败时回滚到上一份可用部署。

不得在输出、日志或提交记录中打印生产环境变量。

## 数据库发布

- 发布前确认 Supabase 项目、备份、迁移顺序和 RLS。
- 已执行迁移不得修改；修复必须新增迁移。
- 应用发布与数据库迁移存在兼容窗口时，先保证新旧应用都能安全运行。
- 破坏性变化必须有明确的恢复步骤和用户授权。

## 阿里云部署约定

当前正式环境使用以下约定：

```text
/srv/dexin/DEXIN-NEBULA             当前在线目录
/srv/dexin/releases/nebula-*        新版本发布目录
PM2: dexin-nebula
应用端口: 3104
Nginx: 80/443 反向代理
```

阿里云部署必须使用独立发布目录：构建成功后再原子切换并重启 PM2，失败时恢复上一目录和进程。2 GB ECS 不适合反复进行高负载远程构建，优先上传本地或 CI 构建产物。
