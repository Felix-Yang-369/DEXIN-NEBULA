# 搜索系统

本文记录德馨星云搜索系统的产品边界、匹配规则与分阶段建设范围。搜索结果必须继承当前账号的页面权限和 PostgreSQL RLS，不能通过标题、摘要、结果数量或错误信息泄露无权访问的对象。

## 搜索层级

1. 全局搜索：查找权限内的功能页面和跨模块业务对象。
2. 模块搜索：在客户、订单、采购、库存、财务等列表中结合关键词与结构化筛选查询。
3. 对象选择器：在业务表单中联想选择客户、产品、供应商、员工和仓库。
4. 德小馨检索：回答自然语言问题并引用来源，不替代要求完整结果集的业务列表搜索。

## 第一阶段现状

全局搜索已覆盖：

- 当前角色可访问的导航功能；
- 员工、制度与知识、产品、客户、供应商；
- 销售订单、采购订单、审批、应收应付单据；
- 公告和企业文件元数据。

业务对象先在 Supabase / PostgreSQL 侧按关键词过滤，再在服务端按相关性排序，每类最多展示五条。编号完全匹配、编号前缀匹配、名称完全匹配、名称前缀匹配和内容包含匹配依次降权。结果仍由各表既有 RLS 控制。

## 统一匹配规则

- 输入先进行 NFKC 规范化、空白合并和长度限制。
- 单号、工号、商品编号、客户编号等标识符优先完全匹配和前缀匹配。
- 名称、简称、品牌、标题等使用不区分大小写的包含匹配。
- 关键词字段之间使用 OR；状态、日期、负责人等结构化筛选与关键词之间使用 AND。
- PostgREST 原始过滤表达式不得直接拼接未经清理的用户输入。
- 不允许固定读取“最近前 N 条”后再在应用内判断是否命中。

## 后续阶段

- 为销售、采购、仓储、财务和审批列表增加独立搜索与筛选。
- 为业务表单建设服务端联想选择器和最近使用记录。
- 为文件正文建设受权限约束的文本提取、OCR 与全文索引。
- 根据真实数据规模增加名称、编号和正文索引，并记录慢查询。
- 增加拼音、别名、同义词、搜索高亮和无结果分析。

生产验收必须至少覆盖普通员工、负责人、财务、董事长和管理员，确认搜索结果、数量和跳转都不会突破其既有数据范围。
