# 德馨星云文件中心需求文档

版本：V1.2  
状态：P0 已开发，待数据库迁移、NAS 联调与业务验收  
适用范围：德馨淼盛内部员工  
产品入口：`/documents`

## 1. 产品定位

文件中心是德馨星云统一的企业文件档案入口，用于保存、检索和受控访问合同、客户资料、供应商资质与内部资料。

文件中心不是普通网盘。它必须将文件与组织、部门、客户、业务编号、有效期和权限关联，并对上传、下载、归档等关键动作保留审计记录。

## 2. 建设目标

- 建立公司内部唯一、可检索的业务文件档案入口。
- 员工不安装、不打开绿联软件，即可直接在德馨星云上传、浏览和下载授权文件。
- 文件正文保存在公司绿联 NAS，避免业务文件分散在个人电脑或聊天工具。
- Supabase 统一管理账号、角色、文件元数据、数据权限和审计记录。
- 员工只能查看职责范围内的文件，敏感文件默认最小授权。
- NAS 或数据库异常时保证文件与元数据不会形成无提示的不一致。
- 为后续文件版本、预览、全文检索和德小馨知识检索提供基础。

## 3. 非目标

V1 不包含以下能力：

- 不允许浏览器、员工电脑或手机直接获得 NAS WebDAV 凭证。
- 不提供匿名链接、互联网公开分享或外部客户自助下载。
- 不替代 NAS 的快照、异地备份和灾难恢复能力。
- 不实现多人实时编辑、在线 Office 协作或桌面同步盘。
- 不自动接管 NAS 中现有的全部公司文件。
- 不在 V1 中提供 OCR、全文索引、文件版本树和批量迁移。

## 4. 用户与核心场景

| 用户 | 核心场景 |
| --- | --- |
| 普通员工 | 上传内部资料，查看本人上传、全公司公开或明确授权的文件 |
| 部门负责人 | 查看本部门文件，监督部门资料归档与共享范围 |
| 销售与客服 | 上传和查看客户资料，并关联客户主档与业务编号 |
| 采购 | 上传和查看供应商资料、资质与合规文件 |
| 人事行政 | 管理合同类与内部制度资料 |
| 财务 | 上传授权合同或供应商资料，不因此获得其他业务模块权限 |
| 系统管理员 | 查看全部文件，管理系统配置、权限和审计，但不代替业务负责人审批 |
| 董事长 | 拥有全公司文件查看、上传、归档和审计权限 |

## 5. 文件夹设计原则

文件中心使用“数据库逻辑文件夹 + NAS 文件正文”的架构：

- 员工看到的文件夹名称、层级、负责人和权限保存在 Supabase。
- NAS 只保存文件正文，不直接决定员工权限。
- 文件夹改名或调整层级时，不要求同步移动 NAS 中的文件正文。
- 员工不能通过 NAS 路径猜测、WebDAV 地址或绿联账号绕过德馨星云。
- 一级文件夹由系统统一维护，业务负责人可以在授权范围内创建二级及以下文件夹。
- 权限默认从父文件夹继承；子文件夹可以提高安全级别，但不能静默降低父级限制。
- 每个文件夹必须指定业务负责人和替补负责人。系统管理员可以查看全部文件并负责系统配置，但不默认成为业务审批人。

NAS 实际路径建议使用稳定 ID，而不是中文文件夹名称：

```text
德馨星云/
└── {organization_id}/
    └── {folder_id}/
        └── {YYYY-MM}/
            └── {file_uuid}.{extension}
```

这样即使“财务管理”改名或移动到新的页面分区，NAS 文件也不需要搬迁。

### 6.2 一级文件夹默认规则

| 一级文件夹 | 默认级别 | 默认可见人员 | 业务负责人 |
| --- | --- | --- | --- |
| 公司公共资料 | L1 全员 | 全体在职员工 | 行政或内容发布负责人 |
| 人力资源 | L3 高级 | 人事、董事长及明确授权人员 | 人事负责人 |
| 财务管理 | L3 高级 | 财务、董事长及明确授权人员 | 财务负责人 |
| 业务管理 | L2 受控 | 销售、客服、相关负责人 | 业务负责人 |
| 供应链管理 | L2 受控 | 采购、仓储、相关负责人 | 供应链负责人 |
| 产品中心 | L2 受控 | 产品、销售及明确授权人员 | 产品负责人 |
| 运营与品牌 | L2 受控 | 运营、市场及明确授权人员 | 运营负责人 |
| 部门空间 | L2 部门 | 对应部门成员 | 部门负责人 |

一级文件夹只定义默认权限。财务与人力资源内部的细分权限暂时沿用一级文件夹默认规则，后续再根据实际岗位和敏感程度优化。薪酬、银行、税务、成本、研发等敏感子文件夹在优化完成前不得扩大默认可见范围。

## 7. 权限级别

| 级别 | 名称 | 默认规则 | 是否允许申请 |
| --- | --- | --- | --- |
| L1 | 公司公开 | 全体在职员工可查看和下载，上传由负责人控制 | 不需要 |
| L2 | 业务受控 | 所属部门、业务角色或项目成员访问 | 允许 |
| L3 | 高级权限 | 专业角色和明确授权人员访问 | 允许，必须说明原因和期限 |
| L4 | 机密权限 | 董事长、系统管理员、业务负责人及逐人授权 | 允许，但必须多级审批 |

文件夹权限拆分为：

- 查看：看到文件夹、文件列表和非敏感元数据。
- 下载：读取文件正文并保存到本地。
- 上传：向文件夹新增文件，不能修改他人文件。
- 维护：编辑元数据、创建子文件夹、归档和管理版本。
- 授权：审批访问申请和管理文件夹成员。

查看权限不自动包含上传或授权权限。系统可以把“查看 + 下载”组合成普通员工看到的“访问权限”。

## 8. 无权限状态与申请访问

### 8.1 页面表现

没有权限的员工可以看到一级文件夹名称、用途说明、权限级别和负责人，但不能看到：

- 文件名和文件数量。
- 客户、供应商、员工或项目名称。
- 文件摘要、更新时间和上传人。
- 子文件夹名称中可能包含的敏感业务信息。

受限文件夹显示锁定状态和“申请查看权限”按钮。L4 文件夹可以由负责人设置为完全隐藏；完全隐藏时只有持有直接链接的员工才能看到统一的无权限页面，不能确认该文件夹是否存在。

### 8.2 申请表单

员工点击“申请查看权限”后填写：

- 申请文件夹：系统自动带入。
- 申请原因：必填，至少 10 个字符。
- 关联客户、项目、采购或工作任务：选填。
- 访问期限：默认 24 小时，也可以申请 7 天、30 天、90 天或长期。
- 是否需要下载：默认需要；L4 文件夹可只批准在线查看。
- 紧急程度：普通或紧急。

员工不能申请“授权”权限。上传和维护权限必须由文件夹负责人主动分配或通过单独的岗位权限流程申请。

### 8.3 审批流程

```text
L2：申请人 → 文件夹负责人 → 生效
L3：申请人 → 直属负责人 → 文件夹负责人 → 生效
L4：申请人 → 直属负责人 → 业务负责人 → 董事长 → 生效
```

规则：

- 申请人不能审批自己的申请。
- 审批人可以缩短期限、取消下载权限或拒绝申请。
- 临时权限到期后自动失效，不影响历史审计。
- 长期 L3/L4 权限必须由董事长或明确的最高业务负责人批准。
- 员工离职、停用、转部门或角色被移除后，系统重新计算并及时撤销不再适用的权限。
- 系统管理员可以查看全部文件、排查流程和执行已批准的授权，但不能代替业务负责人批准权限申请。
- 紧急访问仍需审批；后续可以增加“先授权、限时复核”的紧急机制，但不属于 P0。

### 8.4 申请状态

```text
草稿 → 审批中 → 已通过 → 已生效 → 已到期
               └→ 已拒绝
审批中 → 已撤回
已生效 → 已撤销
```

员工可以在“我的权限申请”查看审批节点、当前处理人、有效期和结果。通过、拒绝、即将到期和撤销时发送站内通知。

## 9. 信息分类

V1 文件分为四类：

| 分类 | 典型内容 | 默认责任范围 |
| --- | --- | --- |
| 合同文件 | 客户合同、供应商合同、劳动或服务协议 | 人事、财务、管理员、董事长 |
| 客户文件 | 客户证照、需求材料、业务附件 | 销售、客服、管理员、董事长 |
| 供应商资质 | 营业执照、授权书、质检与合规文件 | 采购、财务、管理员、董事长 |
| 内部资料 | 流程附件、内部模板、项目资料 | 所有在职员工可按可见范围上传 |

文件分类用于权限和业务检索，不等同于 NAS 物理目录。员工不能通过猜测 NAS 路径绕过系统权限。

## 10. 文件元数据

每份文件至少保存以下信息：

| 字段 | 要求 |
| --- | --- |
| 文件编号 | 系统自动生成，同一组织内唯一 |
| 文件标题 | 必填，2–160 个字符 |
| 文件分类 | 必填，四类之一 |
| 原始文件名 | 系统保存，不作为 NAS 实际文件名 |
| 文件类型与大小 | 系统识别并保存 |
| 描述 | 选填，用于说明用途或内容 |
| 关联客户 | 客户文件可选，只能选择当前组织客户 |
| 往来单位 | 选填，用于供应商或其他主体名称 |
| 业务参考号 | 选填，如合同号、项目号或单据号 |
| 可见范围 | 必填：全公司、本部门或指定角色 |
| 指定角色 | 可见范围为“指定角色”时使用 |
| 所属部门 | 上传时由当前员工档案确定 |
| 上传人、上传时间 | 系统自动记录 |
| 状态 | 有效或回收站（数据库兼容值为 archived） |
| NAS 相对路径 | 系统生成，不向普通用户展示 |
| 所属文件夹 | 必填，决定默认权限和业务位置 |
| 权限级别 | 从文件夹继承，子文件可以提高但不能擅自降低 |

## 11. 上传需求

### 11.1 支持格式

- PDF
- JPEG、PNG、WebP 图片
- Word：DOC、DOCX
- Excel：XLS、XLSX
- 单文件最大 20 MB

服务端必须同时校验登录状态、员工状态、文件分类权限、MIME 类型、扩展名和文件大小。前端校验不能代替服务端校验。

### 11.2 上传流程

1. 员工选择分类并填写文件资料。
2. 系统根据当前账号校验该分类的上传权限。
3. 服务端生成随机 NAS 文件名和组织隔离路径。
4. 文件正文通过 Tailscale 私网和 HTTPS WebDAV 写入 NAS。
5. NAS 写入成功后，在 Supabase 创建文件元数据与上传审计。
6. 页面显示成功结果并在原列表中出现新文件。

### 11.3 一致性要求

- NAS 写入失败：不得创建 Supabase 文件记录，页面显示可重试错误。
- NAS 写入成功、元数据写入失败：服务端自动删除刚写入的 NAS 文件。
- 回滚删除失败：服务端记录不含密码和文件正文的错误标识，交由管理员排查孤立文件。
- 重复提交不得覆盖已有文件；NAS 实际文件名使用随机 UUID。

## 12. 浏览、搜索与提醒

文件列表只能返回当前账号通过数据库权限规则后可查看的记录。

V1 支持：

- 按权限展示一级文件夹、子文件夹和面包屑路径。
- 显示“我的文件”“与我共享”“最近使用”和“我的权限申请”个人视图。
- 按标题、文件编号、往来单位或业务参考号搜索。
- 按合同、客户、供应商、内部资料分类筛选。
- 在有效文件和回收站之间切换。
- 展示文件标题、编号、原始文件名、大小、分类、所属目录和上传人。
- 提供“全部文件、我的文件、最近文件、回收站、权限申请、待我审批”等企业微盘式快捷视图。
- 文件管理人员可以重命名文件、移动到有上传权限的目录、移入回收站并恢复。
- 无数据时显示空状态；数据库失败时显示错误，不持续保留加载骨架。

V1 不使用文件级生效日期或到期日期；权限申请的授权期限仍独立生效。

### 12.1 分栏浏览逻辑

“全部文件”采用类似企业微盘的连续分栏浏览方式：

1. 第一栏固定展示公司共享空间，即八个一级目录；无权限目录仍可见，但显示锁定状态。
2. 第二栏展示当前共享空间的子文件夹；切换文件夹时不离开文件中心。
3. 第三栏展示当前目录中的文件，包含文件名、原始文件名与大小。
4. 第四栏展示所选文件详情，以及下载、重命名、移动和移入回收站等有权限的操作。
5. 顶部固定显示面包屑、上传和新建文件夹入口；按钮根据当前目录权限自动启用或禁用。
6. 小屏设备允许分栏区域横向滚动，不能挤压或隐藏文件操作。

## 13. 下载需求

1. 用户点击下载后，请求先进入德馨星云服务端。
2. 服务端通过 Supabase 会话和 RLS 判断当前员工是否有权查看该文件。
3. 权限通过后，服务端使用专用 WebDAV 账号从 NAS 读取文件。
4. 文件以原始文件名返回，不暴露 NAS 地址、路径或凭证。
5. 下载成功发起后写入下载审计。

下载响应必须禁止公共缓存并设置安全的文件类型响应头。NAS 不可用或文件缺失时，页面分别显示“服务暂时不可用”或“文件不存在，请联系管理员”，不能返回空文件。

## 14. 权限模型

权限由文件分类、可见范围、所属组织、所属部门、角色和上传人共同决定。

### 14.1 查看权限

满足以下任一条件且属于同一组织时可以查看：

- 当前员工是上传人。
- 当前员工是董事长。
- 当前员工是系统管理员。
- 当前员工拥有被明确授权的管理权限。
- 文件为全公司可见。
- 文件为本部门可见，且员工属于文件所属部门。
- 文件为指定角色可见，且员工拥有其中一个角色。

### 14.2 上传权限

| 分类 | 可以上传 |
| --- | --- |
| 合同文件 | 人事、财务、管理员、董事长 |
| 客户文件 | 销售、客服、管理员、董事长 |
| 供应商资质 | 采购、财务、管理员、董事长 |
| 内部资料 | 所有在职员工 |

### 14.3 归档权限

- 上传人可以归档本人上传的文件。
- 人事可以归档职责内的合同文件。
- 销售、客服可以归档职责内的客户文件。
- 采购可以归档职责内的供应商文件。
- 董事长拥有全部归档权限。
- 系统管理员可以查看全部文件，但上传、维护、归档和授权仍按对应操作权限执行。

## 15. 文件生命周期

```text
上传中 → 有效 → 回收站 → 已恢复
   └─失败→ 不创建记录或自动回滚
```

- “有效”文件可以正常检索和下载。
- “回收站”表示不再作为当前业务文件展示，但文件正文仍保留且可由授权人员恢复。
- V1 不提供员工永久删除功能。
- 重命名、移动、移入回收站和恢复操作必须记录操作人、时间和文件编号。
- 后续若增加彻底删除，必须采用回收站、保留期和二次审批，不得直接删除。

## 16. 存储与安全架构

```text
员工浏览器
  → 德馨星云 Next.js 服务端
    → Supabase：Auth、逻辑文件夹、权限申请、文件元数据、RLS、审计
    → Tailscale 私网
      → 绿联 NAS WebDAV：文件正文
```

安全要求：

- WebDAV 使用 NAS 专用 Standard User，只允许读写“德馨星云”共享文件夹。
- NAS 账号不得拥有管理员权限，不与员工个人账号共用。
- WebDAV 地址、用户名、密码和证书配置只能保存于阿里云服务端环境变量。
- 浏览器不能直接访问 NAS，也不能获得永久下载地址。
- 员工上传和下载文件不需要安装或打开绿联软件。
- ECS 与 NAS 之间只通过 Tailscale 私网连接，不对公网开放 NAS WebDAV 端口。
- WebDAV 必须使用 HTTPS；正式环境优先使用可信证书或受控 CA。
- 日志不得记录密码、Authorization 请求头或文件正文。
- 数据库继续使用组织边界和 PostgreSQL Row Level Security。

具体连接配置见 [绿联 NAS 文件中心接入](../integrations/nas-webdav.md)。

## 17. 审计要求

V1 至少记录：

- 文件上传：操作人、组织、文件 ID、文件编号、分类和时间。
- 文件下载：操作人、组织、文件 ID、标题和时间。
- 文件归档：操作人、组织、文件 ID、标题和时间。
- 权限申请：申请人、文件夹、原因、期限、审批节点和结果。
- 权限变化：授权人、被授权人、权限类型、生效时间、到期时间和撤销原因。

审计日志只保存必要元数据，不保存文件正文、WebDAV 密码或认证头。审计记录不随文件归档而删除。

## 18. 可用性与异常状态

| 场景 | 用户结果 | 系统要求 |
| --- | --- | --- |
| 页面数据加载中 | 显示接近真实布局的骨架 | 数据到达后原位替换，避免明显跳动 |
| 数据查询失败 | 显示错误和重试入口 | 不永久显示骨架 |
| 无上传权限 | 不提供对应分类，并在服务端再次拒绝 | 不能仅隐藏按钮 |
| 文件格式或大小错误 | 明确提示支持格式和 20 MB 限制 | 不向 NAS 写入文件 |
| NAS 无法连接 | 提示文件服务暂不可用 | 不创建元数据 |
| NAS 认证失败 | 提示联系管理员 | 服务端只记录错误类型 |
| NAS 文件缺失 | 提示文件不存在 | 不返回空响应，并保留元数据供排查 |
| 元数据保存失败 | 提示资料保存失败 | 删除刚上传的 NAS 文件 |
| 下载越权 | 提示文件不存在或无权下载 | 不访问 NAS 文件正文 |
| 文件夹无权访问 | 显示锁定说明和申请按钮 | 不返回文件列表或敏感统计 |
| 权限申请处理中 | 显示当前节点和预计处理人 | 防止重复申请 |
| 临时权限到期 | 显示权限已到期，可重新申请 | 服务端立即停止访问 |

## 19. 运维与恢复要求

生产启用前必须完成：

- NAS 共享文件夹快照或定期备份策略。
- Supabase 数据库备份与恢复方案。
- NAS 和数据库备份的恢复演练，确认元数据与文件正文可以重新对应。
- WebDAV 专用账号密码轮换流程。
- NAS 容量、WebDAV 可用性和应用错误日志的日常检查。
- Tailscale 节点失效、NAS 重启和 ECS 重启后的自动恢复验证。

NAS 与 Supabase 是两套独立数据源。只恢复其中一套不能视为完整恢复。

## 21. P0 验收标准

P0 只有同时满足以下条件才可标记为已上线：

1. 员工无需绿联软件即可在德馨星云展开授权文件夹并上传、下载文件。
2. 八个一级文件夹、默认权限级别和业务负责人配置正确。
3. 无权限员工只能看到允许公开的文件夹信息，不能获得文件名、数量和敏感元数据。
4. 无权限员工可以提交“申请查看权限”，并看到完整审批状态。
5. L2、L3、L4 按对应审批流程生效，申请人不能自批。
6. 临时权限默认有效 24 小时，到期后列表与下载权限立即失效。
7. 有权限账号可以上传 20 MB 以内的全部支持格式，NAS 中出现对应文件。
8. Supabase 文件记录包含正确的组织、文件夹、权限级别、上传人、分类、大小和 NAS 相对路径。
9. 下载返回原始文件名和完整内容，浏览器看不到 NAS 凭证或直连地址。
10. 普通员工、部门负责人、财务、人事、管理员和董事长的范围符合权限矩阵。
11. 复制他人无权文件的下载地址后仍被服务端拒绝。
12. NAS 停止服务时上传失败且数据库不新增文件记录。
13. 模拟元数据写入失败后，NAS 不残留刚上传的文件。
14. 上传、下载、归档、权限申请、审批、到期和撤销均产生正确审计记录。
15. 回收站文件不出现在有效文件列表，但可以按权限查看并恢复。
16. 加载、空数据、查询失败、NAS 失败和文件缺失均显示明确状态。
17. ESLint、TypeScript、自动化测试和生产构建通过。
18. NAS 备份、数据库备份和回滚方式已由管理员确认。
